# Focuser - Prompts & Specification Record

This log records the development prompts and architectural design specs for building the Focuser MVP.

---

## Phases 6–9 Specifications (Windows FocusController, Countdown, Pairing, Fail-safe)

### Phase 6 — Windows Focus Controller
- **Protected Windows**: Codeforces browser window, Focuser Agent, System Taskbar/Shell handles (`ProtectedAppsManager`).
- **Distracting Windows**: Enumerated via Win32 `User32.dll` (`EnumWindows`, `IsWindowVisible`, `GetWindowText`). Temporarily minimized via `ShowWindowAsync(hWnd, SW_MINIMIZE)`.
- **Restoration**: Restored via `ShowWindowAsync(hWnd, SW_RESTORE)` on `exitFocus()`.
- **Safety**: Zero process termination or data loss risk.

### Phase 7 — Reliable Focus Countdown
- **Authoritative Agent Timer**: `startedAt`, `endsAt` Unix timestamps generated by Agent.
- **Auto Expiration**: `Date.now() >= endsAt` triggers automatic `exitFocus()` and window restoration.
- **Browser Resilience**: Reconstructs countdown on browser refresh or reconnect using `endsAt - Date.now()`.

### Phase 8 — Explicit Local Agent Pairing
- **6-Digit Pairing Code**: Random 6-digit code displayed in Agent System Tray context menu.
- **Explicit Pairing**: Client submits code via `{ type: "pair", code: "768290" }`. Single-use code invalidated upon success; paired token saved to `userData/pairing.json`.

### Phase 9 — Fail-Safe Recovery
- **Local Persistence**: Active session state saved to `userData/active-session.json` and window handles to `userData/window-state.json`.
- **Startup Reconciliation**: On restart or sleep wake, agent checks for unfinished sessions. If expired, restores desktop layout and clears state.
